# 졸업생 명부 가져오기

## 자료 범위

- 사용자가 제공한 HWPX의 졸업생 명부 표에서 20~97회만 사용한다. 1~19회는 사용자 요청으로 제외한다. 원문 파일은 수정하지 않는다.
- 원문 4,859건 중 44회 괄호 누락 1건은 운영자 확인에 따라 정정하고, 62회 이름 마지막 글자 불명 1건은 보류한다. 등록 대상은 4,858건이다.
- 같은 기수·이름의 34개 묶음, 이름·지역까지 같은 15개 묶음은 임의로 합치지 않는다. 인원 수가 아닌 원문 등록 건수로 보고한다.
- 이름과 괄호 속 지역을 분리한다. 지역 `ㅇㅇ` 등은 미상으로 저장하되 원문을 출처 기록에 보존한다. 이번 자료의 지역 미상은 784건이다. 명부 지역을 회원의 현재 거주지로 복사하지 않는다.
- 졸업연도는 표의 날짜에서 읽는다. 20회는 1947년, 97회는 2024년이다. 기존의 기수+1926 계산은 3회부터 한 해 차이가 있어 회원가입 및 기존 자동 계산값도 보정한다.
- 2026-10-14 운영자가 로그인 회원 대상 이름·기수 검색 공개 확인 완료를 명시했다. 자동으로 회원 계정을 만들거나 기존 회원과 연결하지 않는다. 지역과 자료 출처는 관리자에게만 보인다.

## 로컬 자료 준비

실제 HWPX, 정정 내역, CSV, 등록 SQL은 소스·마이그레이션·테스트 fixture에 넣지 않는다.
공유 가능한 것은 추출 도구와 가상 데이터 테스트뿐이다. `.harness/`와 `.imports/`는 Git에서 제외한다.

```powershell
python -X utf8 scripts/import_roster.py "문서의 절대 경로.hwpx" --corrections .harness/roster-corrections.json --publication-confirmed --consent-note "운영자가 확인한 날짜와 공개 범위"
```

정정 내역이 없으면 `--corrections`를 생략한다. 공개가 확인되지 않았으면 마지막 두 옵션을 모두 생략하며 비공개 SQL이 생성된다. 이 도구는 DB에 연결하지 않는다.

정정 JSON은 `출처ID:기수:4자리순번`을 키로 하고 `original`, `replacement`, `reason`을 기록한다. 원문이 일치하지 않거나 정정 키를 찾지 못하면 생성을 중단한다. 승인받지 않은 이름의 추정·보완은 하지 않는다.

산출물은 `.harness/roster-import/`에 생성된다.

| 파일 | 내용 |
| --- | --- |
| `import.sql` | 등록 가능한 항목만 담긴 트랜잭션 SQL |
| `review.csv` | 원문·이름·지역·기수·연도·보류 사유 대조표 |
| `report.json` | 원본 SHA-256, 기수별 건수, 동명이인 묶음, 보류 항목 |

## 운영 서버 반영

1. 변경 코드를 검증 후 별도 승인된 push로 배포한다. 백엔드의 Flyway V3/V4 적용이 먼저 필요하다. push만으로 실제 명부가 등록되지는 않는다.
2. 실제 운영 데이터가 있다면 기존 DB 백업 절차를 먼저 확인한다. DB를 초기화하지 않는다.
3. WinSCP로 **`import.sql`만** 서버의 기존 `/home/ubuntu/bongrae-alumni/backups/` 폴더에 업로드한다. 공개 `uploads` 폴더에는 넣지 않는다. `backups/*.sql`은 Git에서 제외되어 있다.
4. 서버에서 실행한다. 아래 과정은 앱·DB 컨테이너를 재생성하지 않는다.

```bash
cd /home/ubuntu/bongrae-alumni
chmod 600 backups/import.sql
sudo docker exec -i bongrae-postgres sh -c 'exec psql -X -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' < backups/import.sql
```

첫 실행 예상 결과는 `source_records=4858, inserted_records=4858, skipped_records=0`이다. 같은 파일의 재실행은 추가 0건이다. 실패 시 트랜잭션 전체가 취소되므로 에러를 무시하고 일부 SQL만 실행하지 않는다.

처리 완료한 원문 위치는 `alumni_import_keys`에 남긴다. 관리자가 비공개로 바꾼 항목은 공개로 되돌리지 않고, 삭제한 항목도 다시 생성하지 않는다. 기존 이름·기수·연도·지역과 충돌하면 전체 등록을 중단하고 사람이 대조한다. 동명이인이나 기존 수기 명부는 자동으로 병합하지 않는다.

5. 관리자 > 동문 명부에서 건수와 지역·연도를 확인하고, 일반 회원으로 20회/97회 검색을 확인한다. 비로그인 검색은 계속 차단되어야 한다. 서버의 명부 SQL도 개인정보 자료로 접근을 제한하고 보관 정책에 따라 관리한다.

## 검증

`node scripts/verify.mjs all`은 원본 명부 없이 가상 자료로 실행된다. 실제 문서는 별도로 원문 항목 수, 정정 승인, 보류 1건, 기수별 등록 건수, 검색 접근 권한을 대조한다. 자동 검사를 운영 DB에 연결하지 않는다.

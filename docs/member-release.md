# 회원·동문 검색·게시판 운영 전환

## 현재 범위

회원가입 즉시 로그인하여 동문 검색과 자유게시판 작성이 가능하다. 별도 가입 승인 단계는 없다.
공지·행사·사진/영상·회무 글은 ADMIN과 SUPER_ADMIN만 작성한다. 총괄 관리자는 최대 1명이다.
장학사업은 추진 중이며 SMS/이메일은 동의만 저장한다. 발송, 비밀번호 재설정, 본인인증은 미구현이다.

회원 검색은 본인이 정보 제공에 동의한 계정과 동의를 확인하여 등록한 미가입 명부를 대상으로 한다.
이름과 기수 일치만으로 본인인지 판단하거나 자동 연결하지 않는다. 관리자 > 동문 명부에서 확인 후 연결한다.
명부의 미가입 표시는 회원 계정과 연결되지 않은 상태를 뜻한다. 연결 전에는 동일인이 중복으로 보일 수 있으므로 확인 후 정리한다.
연결된 회원은 해당 회원의 공개 동의를 따르며 검색 결과에 전화·이메일·지역을 포함하지 않는다.

## 개발 실행

앱 폴더에서 실행한다. Docker Desktop이 켜져 있어야 한다.

```powershell
docker compose -f docker-compose.dev.yml up -d
```

- 미리보기: http://localhost:8088 (또는 http://localhost:3001)
- Docker 백엔드 직접 접속: http://localhost:18080/api/health. 포트 충돌 시 DEV_BACKEND_PORT로 변경한다.
- 소스 변경 시 프론트 갱신, 백엔드 소스 감지 후 재시작. 변경된 Java 컴파일 동안 잠시 연결이 끊길 수 있다.
- 프론트 의존성 변경 시 `docker compose -f docker-compose.dev.yml restart frontend`.
- 개발 포트는 로컬 컴퓨터에서만 접근한다. 운영 서버에는 개발 Compose를 사용하지 않는다.
- 소스 직접 실행 시 프론트의 `/api`는 기본 `http://127.0.0.1:8080`으로 전달된다. 필요하면 서버 전용 `BACKEND_URL` 지정.
- 개발 Compose는 프론트 `.next`와 백엔드 `build`/`.gradle`을 별도 볼륨에 두어 호스트 하네스 검사와 빌드 산출물을 공유하지 않는다.

전체 개발 서비스를 띄운 뒤 프론트 폴더에서 `node scripts/smoke-local.mjs`로 실제 연결 검사를 추가로 실행할 수 있다.
이 검사는 localhost/127.0.0.1만 허용하고 가상 회원·게시물·사진을 생성한 후 삭제한다. 운영 DB 터널에는 사용하지 않는다.

## 총괄 관리자 최초 생성

코드에 기본 관리자 암호는 없다. 운영 서버 `.env`에 다음 3개 값을 직접 정한다. 비밀번호는 채팅·Git에 넣지 않는다.

```dotenv
BOOTSTRAP_ADMIN_USERNAME=직접정한영문아이디
BOOTSTRAP_ADMIN_PASSWORD=직접정한16자이상비밀번호
BOOTSTRAP_ADMIN_EMAIL=실제관리자이메일
```

아이디는 소문자 영문·숫자·밑줄·점·하이픈 4~30자, 암호는 16자 이상, UTF-8 72바이트 이하.
SUPER_ADMIN이 없는 경우에만 새 계정을 생성한다. 기존 아이디/이메일을 자동 승격하지 않으며 중복이면 시작을 거부한다.
생성 확인 후 `.env`의 초기화 값을 지우고 백엔드를 재생성하여 컨테이너 환경에서도 제거한다. 기존 계정은 유지된다.
총괄 관리자 로그인 > 관리자 > 회원 및 권한에서 실제 임원임을 확인하고 ADMIN 지정 또는 MEMBER로 회수한다.
총괄 관리자 변경·복구는 공개 API로 제공하지 않는다. 서버 운영자가 DB 관리 절차로 처리해야 한다.

## 서버 반영 순서

1. 개인정보 담당자·연락처와 아래 운영 정책을 먼저 확정한다. 테스트 검증을 운영 동의 절차 완료로 보지 않는다.
2. 기존 실제 회원/게시물이 있다면 DB 백업을 확보한다. 테스트 DB를 자동으로 지우거나 초기화하지 않는다.
3. 서버의 `docker-compose.yml`을 이번 버전으로 별도 전달하고, `.env`에 관리자 초기화 값을 설정한다.
4. 검증 통과 후 사용자가 승인한 push/배포를 진행한다. 이미지 배포는 서버 Compose·Nginx 파일을 자동 갱신하지 않는다.
5. 백엔드는 시작할 때 Flyway V1/V2를 적용한다. 비어 있는 DB는 생성하고, 기존 users/alumni_profiles DB는 baseline 0 뒤 추가 스키마를 적용한다.
6. 로그와 `/api/health`를 확인하고, HTTPS에서 가입·로그아웃·관리자 작성·일반회원 거부를 점검한다.
7. 관리자 초기화 값을 제거하고 이미지 배포에서 사용하는 것과 동일한 Compose 파일 조합으로 백엔드 컨테이너를 재생성한다.

기존 계정의 ID·암호·프로필은 유지한다. 이전 로그인 토큰은 더 이상 사용하지 않으므로 재로그인이 필요하다.
기존 프로필 공개 설정은 새 정보 제공 동의의 증거가 아니므로 비공개로 바뀌며 내 정보에서 새 동의를 받아야 한다.
대소문자만 다른 아이디/이메일 또는 SUPER_ADMIN 2명 이상이 이미 있으면 유일성 검사로 전환이 중단된다. 운영자가 확인하고 정리해야 한다.
마이그레이션은 이미 적용된 파일을 수정하지 말고 V3 이후 새 파일로 추가한다. 운영 이전 DB의 실제 전체 덤프는 검사하지 않았다.

## 인증과 파일

- HttpOnly/SameSite=Lax 세션 쿠키, 운영은 Secure 쿠키이므로 HTTPS 필수. 마지막 활동 후 12시간 만료.
- 세션은 PostgreSQL에 저장되어 컨테이너 재시작에도 유지된다. 요청마다 현재 DB 권한을 확인한다.
- POST/PUT/PATCH/DELETE는 CSRF 토큰 필수. 브라우저 코드가 같은 출처의 `/api/auth/csrf`에서 받아 요청한다.
- 사진 PNG/JPEG 및 MP4: 각 16MB, 글당 5개. 브라우저 지원 MP4 코덱을 사용해야 한다. 서버 변환/압축은 하지 않는다.
- 신규 첨부파일은 DB `board_media.content`에 저장된다. 업로드 후 미게시 상태에서는 작성자만 읽을 수 있고, 글에 저장하면 공개된다.
- 파일 삭제는 게시글 삭제와 함께 처리한다. 미사용 임시 파일은 다음 업로드 요청 때 24시간이 지난 것을 정리한다.
- 기존 `uploads` 공개 폴더는 그대로 두지만 새 첨부파일은 이 폴더에 저장하지 않는다. DB 백업에 파일도 포함되므로 용량을 모니터링한다.
- 게시글은 일반 텍스트로 표시해 임의 HTML 실행을 허용하지 않는다. 수정 버전이 충돌하면 재확인을 요구한다.

## 개인정보 문서 공개 전 확인

사용자가 담당자와 연락처를 미정으로 답했으므로 `/legal/privacy`에 미정과 확정 필요를 명시했다.
문서는 현재 구현에 맞춘 초안이며 법률 검토 완료나 법령 준수를 보증하지 않는다.

- 개인정보 보호책임자/담당 부서 및 실제 이메일·전화, 권리행사 접수 절차.
- 가비아 실제 계약의 수탁자 법인, 위탁 업무, 저장 국가와 재위탁/국외 이전 여부.
- 웹 서버 접속 로그·DB 백업·운영 감사 기록의 보유 기간, 파기 절차 및 접근자.
- 계정 본인확인, 만 14세 이상 확인의 운영 방식. 현재는 본인 확인 체크를 받으며 만 14세 미만 가입/법정대리인 확인은 제공하지 않는다.
- 미가입 명부의 정보 제공 동의 증빙과 철회 창구. 첨부 원본 명단을 동의 확인 없이 자동 공개하지 않는다.
- SMS/이메일 발송 도입 시 위탁 고지, 거부 절차, 광고성 정보 및 야간 발송에 필요한 별도 요건 검토.
- 공개 모집 전에 가입 남용·로그인 시도 제한, 계정 복구, 보안 업데이트·관제 운영을 마련한다.
